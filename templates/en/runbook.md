# Memory Snapshot Sync RUNBOOK ({{SCHEDULE_TIME}} Cron / Manual Run)

Your job: incrementally distill changed memory entries into compact `AGENTS.md` hot snapshot caches in strict order: **Stage 1: Per-Workspace -> Stage 2: Global**. The Python script handles hashing, diffs, schema checks, backups, and atomic writes; your job is to update the fixed snapshot sections from the diffs.

Tool: `{{PYTHON_CMD}} "{{OPS_DIR}}/memsync.py" <command>` (`memsync` below).
Stdout returns compact ASCII status only; read generated report files to inspect full details.

## Hard Prohibitions
1. Never edit `{{MEMORY_HOME}}/AGENTS.md` or any `<workspace>/AGENTS.md` directly; `memsync apply` is the sole writer.
2. Never modify `GEMINI.md`, `memories/*.md`, `config.json`, or `sync-state.json` during snapshot sync.
3. Write draft files strictly inside `{{OPS_DIR}}/work/`.
4. Never copy secrets, API keys, tokens, or `sync: never` sensitive internals into any `AGENTS.md`.

## Execution Steps

### Step 1 · Lint Check
Run `memsync lint` and read `work/lint-<today>.md`. Note any ERROR/WARN for the final report; warnings do not block sync unless `apply` fails.

### Step 2 · Build Incremental Sync Plan
Run `memsync sync-plan` and read `work/sync-plan-<today>.md`:
- If index-only mode (`SKIP_ALL`) or all scopes show `SKIP`, exit with the SKIP summary immediately. Never rewrite unchanged files.
- Skip Stage-1 draft/apply for any workspace marked `SKIP_AGENTS` (`manage_agents=false`).

### Step 3 · Stage 1: Process Changed Workspaces
For each workspace `<ws>` marked `NEEDS_UPDATE`:
1. Read `work/sync-ws-<ws>-<today>.md` (if flagged `FOREIGN_AGENTS`, keep original memory entries untouched and warn the user in the final report to review the `backup/` copy).
2. Merge current `AGENTS.md` with `[NEW]`, `[MODIFIED]`, and `[DELETED]` diffs into `{{OPS_DIR}}/work/draft-ws-<ws>-<today>.md` using these fixed sections:
   - Header note: auto-generated by memory sync ({{SCHEDULE_TIME}} / manual), do not edit manually, workspace name + root path anchor, sync date;
   - Pointers to `<workspace>/GEMINI.md` and `{{MEMORY_HOME}}/GEMINI.md`;
   - `## 1. Active Project Progress & Decisions` (active `project` state; prune deleted/completed items);
   - `## 2. Project-Specific Conventions & Pitfalls` (repo-specific constraints only; never duplicate global rules).
3. Run `memsync apply --scope <ws> "{{OPS_DIR}}/work/draft-ws-<ws>-<today>.md"` and check the report for `ERROR 0`.

### Step 4 · Stage 2: Roll Up Global `AGENTS.md`
If `[global]` is marked `NEEDS_UPDATE`:
1. Run `memsync global-input` and read `work/sync-global-<today>.md`.
2. Write the updated global snapshot to `{{OPS_DIR}}/work/draft-global-<today>.md` using these fixed sections:
   - Header note: auto-generated by memory sync, do not edit manually, sync date;
   - Pointers to `{{MEMORY_HOME}}/GEMINI.md` and `{{MEMORY_HOME}}/memories/`;
   - `## 1. User Profile & Core Preferences` (`user` entries);
   - `## 2. Workspaces & Active Projects` (1-2 live summary lines per enabled workspace from Stage-1 snapshots + cross-workspace `project` entries);
   - `## 3. General Engineering Conventions` (`feedback` entries);
   - `## 4. Environment & Tooling Quick Reference` (distill key tool paths, package managers, and OS gotchas from `memories/local-installed-tools.md` and end Section 4 with a fixed pointer to it if that file exists; keep `sync: never` secret pointers strictly redacted).
3. Run `memsync apply --scope global "{{OPS_DIR}}/work/draft-global-<today>.md"` and verify `ERROR 0` (when `cross_tool_sync.enabled=true`, external targets are automatically backed up and synced).

## Final Output Format
```text
Memory Sync YYYY-MM-DD: OK | SKIP(0 changes) | FAIL
- lint: ERROR n / WARN m (work/lint-YYYY-MM-DD.md)
- workspaces: <ws>: +a/-b lines (x bytes) | SKIP | SKIP_AGENTS
- global: +a/-b lines (y bytes) | SKIP
```
